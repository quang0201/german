# Workflow Gates

## Gate A — Product truth
Know:
- primary user;
- primary job;
- decision/action the screen enables;
- product category and operating context;
- brand or existing design language;
- technical and accessibility constraints.

## Gate B — Visual contract
Record:
- design thesis;
- reference evidence and anti-references;
- type hierarchy;
- palette roles;
- grid/container strategy;
- spacing rhythm;
- density target;
- radius/elevation philosophy;
- motion philosophy;
- imagery/iconography strategy;
- component/state rules.

## Gate C — Implementation
Confirm:
- framework conventions respected;
- semantic structure;
- reusable primitives;
- content overflow handled;
- loading/empty/error/success states where applicable;
- no accidental hardcoded divergence from tokens.

## Gate D — Rendered evidence
Inspect:
- first viewport;
- alignment and rhythm;
- type scale and line length;
- contrast and emphasis;
- data density;
- control hierarchy;
- long-content behavior;
- mobile/compact reflow;
- hover/focus/active/disabled states.

## Gate E — Final review
Reject completion if:
- the page looks templated or generic without product justification;
- hierarchy is unclear;
- mobile is an afterthought;
- source code is the only evidence;
- screenshot shows overflow, awkward wrapping, random spacing, or weak alignment.
